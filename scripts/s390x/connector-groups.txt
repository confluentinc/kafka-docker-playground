# s390x connector group reference — simple local lookup for the VM-based
# certification workflow (used by scripts/s390x/certify-connector.sh Step 1
# and connect/CERTIFYING_S390X.md).
#
# This is NOT a CI/Semaphore test list — that lives in connect-ci-cd-pipelines
# (cp-connector-tests/tests.txt), is shared across all architectures, and
# already tracks real connector owners. Nothing here feeds a pipeline; it's
# purely a quick "what group is this connector in" reference. Re-evaluate
# whether this file is worth keeping in sync as certification progresses.
#
# Full rationale / images / blockers per connector: see Appendix A of the
# "s390x KDP Testing - Certification guide for SMEs" page on Confluence,
# which is the authoritative per-connector list. This file is a local mirror
# for the tooling to grep against; if a connector's group here ever
# disagrees with Appendix A (or is missing from one but not the other),
# Confluence wins and this file should be corrected to match.
#
# Groups:
#   Cloud/SaaS - calls a real cloud API, no local service container to run
#   Group 1    - service image already publishes an s390x manifest
#   Group 2    - needs a minor image version/tag bump to get an s390x manifest
#   Group 4    - no native s390x image, QEMU emulation is a viable first pass
#   Group 3    - licensed/commercial, no public s390x image; needs manual,
#                out-of-band image provisioning, not covered by this workflow
#                (Group 3 marked with * below also requires vendor license
#                acceptance even where a multi-arch image exists)
#
# Format: connect-<dir>: Group
